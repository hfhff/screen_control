# 월간 일정 기반 앱 차단 — 기획서

> Android에서 기본 템플릿을 원하는 날짜에 적용하고, 날짜마다 다른 앱과 시간을 차단하는 개인용 앱.

프로젝트 이름은 임시로 **월간 차단**이며, 이 저장소에는 첫 Android MVP가 구현되어 있다.

## 구현 원리와 개발 기록

이 프로젝트는 Android에서 날짜별로 다른 앱과 시간대를 차단하는 개인용 집중력 앱이다. 기본 템플릿을 만든 뒤 달력의 날짜에 적용하고, 사용자가 `차단 시작`을 눌렀을 때만 감시를 시작한다.

초기 구현은 `UsageStatsManager`로 최근 사용 앱을 조회하고 오버레이를 띄우는 방식이었다. 일부 제조사에서 앱 전환 이벤트를 늦게 기록했고, Gemini처럼 실제 화면을 다른 호스트 패키지가 표시하는 경우도 있어 차단이 누락됐다. 현재는 `AccessibilityService`가 창 전환 이벤트를 직접 감지하고 `TYPE_APPLICATION_OVERLAY` 차단 화면을 표시한다. UsageStats와 foreground service는 보조 감시와 재시작에 사용하며, Gemini 패키지와 Google 앱 호스트 패키지 차이도 별칭으로 처리한다.

## 기능 추가 내역

- 기본 템플릿에 앱 여러 개와 시간대 여러 개를 저장하고 기존 시간대를 수정하거나 삭제할 수 있다.
- 날짜별 일정은 템플릿과 독립적으로 저장되므로 날짜마다 앱과 시간이 다를 수 있다.
- 달력은 일요일부터 시작하며 일정이 있는 날짜만 `차단됨`으로 표시한다.
- 토요일은 파란색, 일요일과 대한민국 공휴일은 빨간색으로 표시한다.
- `이번 달 일~목에 템플릿 적용`은 금요일·토요일·공휴일을 제외한다.
- `당월 차단 일정 모두 삭제`는 현재 달력에 표시 중인 달의 날짜별 일정만 삭제하고 기본 템플릿은 유지한다.
- 차단 화면에는 홈 이동과 현재 일정 동안 해제 기능이 있다.

## 보안과 권한

- 사용 정보 접근: 현재 앱 감지 보조용
- 접근성 서비스: 앱 전환을 즉시 감지하는 핵심 차단용
- 다른 앱 위에 표시: 차단 화면 표시용
- foreground service와 알림: 백그라운드 감시 유지용

앱 이름과 화면 전환 정보는 기기 안에서만 처리하며 외부 서버로 전송하지 않는다. 접근성 서비스는 Play 배포 시 사용 목적 고지, 명시적 동의, Play Console 신고가 필요하다. debug APK는 Play Protect 경고가 발생할 수 있으므로 개인 테스트는 ADB, 공개 배포는 release 서명과 Play 내부 테스트를 사용한다.

## 시행착오와 해결

1. 일정 저장 후 자동 시작하던 흐름을 사용자가 직접 시작하는 흐름으로 변경했다.
2. 단순 UsageStats 조회만으로는 기기별 이벤트 지연이 있어 접근성 서비스로 전환했다.
3. Gemini 패키지와 실제 Google 앱 호스트 패키지가 달라 별칭 매칭을 추가했다.
4. 달력의 월 이동과 삭제 기준이 선택 날짜와 달라질 수 있어 표시 중인 달을 별도로 관리한다.
5. 기존 시간대가 삭제만 가능했던 편집기를 시간 수정·삭제 버튼으로 개선했다.

## 빌드, 테스트, 설치

```powershell
$env:JAVA_HOME='E:\game\tools\jdk-17\jdk-17.0.20.1+1'
$env:ANDROID_SDK_ROOT='E:\game\tools\android-sdk'
$env:ANDROID_USER_HOME='E:\control\.android-home'
$env:GRADLE_USER_HOME='E:\control\.gradle-home'
.\gradlew.bat lintDebug assembleDebug
.\install-debug.ps1
```

APK는 `app/build/outputs/apk/debug/control.apk`에 생성된다. `install-debug.ps1`은 `adb install -r`로 기존 앱 데이터를 유지하면서 설치한다. 일정 계산 테스트는 `tools/ScheduleRulesSelfTest.java`로 실행한다.

## 1. 만들려는 앱

사용자는 기본 템플릿에 자주 쓰는 앱과 시간대를 저장한다. 달력에서 원하는 날짜에 템플릿을 적용하거나 그날만 사용할 앱과 시간을 직접 설정한다.

이 앱에서 **제한 시간은 앱을 사용할 수 없는 시간대**를 뜻한다. 하루 사용량이나 한 번에 사용할 수 있는 시간을 제한하는 방식은 첫 버전의 중심 기능이 아니다.

ScreenZen과 같은 앱 사용 관리 도구에서 출발하되, 월간 일정 편집과 날짜별 예외 설정을 핵심으로 한다.

## 2. 확정된 요구사항

| 항목 | 요구사항 |
| --- | --- |
| 대상 플랫폼 | Android |
| 차단 방식 | 사용자가 직접 지정한 시간대에 대상 앱 실행을 제한 |
| 계획 주기 | 한 달에 한 번 월간 일정을 정리할 수 있어야 함 |
| 기본 일정 | 사용자가 저장한 앱 목록과 시간대 템플릿 |
| 날짜별 일정 | 날짜마다 다른 앱 목록과 시간대를 직접 설정하거나 템플릿 복사 |
| 해제 | 차단 중에도 사용자가 즉시 해제 가능 |

## 3. 첫 버전의 사용자 흐름

1. 기본 템플릿에 차단할 앱과 시간대를 저장한다.
2. 월간 달력에서 날짜를 선택한다.
3. `기본 템플릿 적용`을 누르거나 그 날짜의 앱과 시간을 직접 설정한다.
4. 권한을 허용한 뒤 홈 화면의 `차단 시작`을 누르면 차단 감시가 시작된다.
5. 차단 시간에 대상 앱을 열면 차단 안내 화면이 나타난다.
6. 필요하면 `지금 해제`를 눌러 즉시 사용한다.

### 사용 예시

- 기본 템플릿: 인스타그램·유튜브를 09:00~18:00에 차단.
- 15일: 템플릿을 적용해 같은 앱과 시간을 자동으로 추가.
- 22일: 템플릿 대신 게임을 22:00~24:00에 직접 설정.
- 긴급 사용: 차단 중 필요한 앱이 있으면 즉시 해제.

위 날짜와 시간은 설명용이며 사용자가 자유롭게 입력한다.

## 4. 주요 기능과 화면

### 홈 — 오늘의 일정

- 차단 실행 상태와 오늘 일정 표시.
- 오늘 적용되는 차단 시간대와 대상 앱 표시.
- 권한이 준비되면 사용자가 `차단 시작`을 눌러 감시를 시작.
- 기본 템플릿 편집으로 이동.

### 기본 템플릿

- 차단 앱을 검색하고 아이콘·패키지명과 함께 선택.
- 원하는 시간대를 직접 입력하고 여러 구간 추가.
- 저장한 템플릿을 여러 날짜에 복사 적용.

### 월간 달력

- 월 이동 및 날짜 선택.
- 일정이 저장된 날짜와 비어 있는 날짜를 구분.
- 날짜를 누르면 그날의 앱과 실제 시간표 확인.
- 템플릿 적용 여부와 관계없이 날짜별로 독립 저장.

### 날짜별 편집

- 해당 날짜의 앱과 시간대를 추가·수정·삭제.
- `기본 템플릿 적용`으로 템플릿의 앱과 시간대를 복사.
- 날짜별 일정 삭제.
- 날짜별 수정은 다른 날짜나 템플릿을 변경하지 않음.

### 차단 안내

- 현재 차단 중이라는 안내와 종료 예정 시간 표시.
- `돌아가기`와 `지금 해제` 제공.
- 즉시 해제에는 대기 시간, 비밀번호, 추가 과제를 요구하지 않음.
- 무의식적인 실행을 한 번 끊도록 `지금 꼭 열어야 하나요?`라는 짧은 문구를 표시.

## 5. 일정 적용 규칙

| 상황 | 동작 |
| --- | --- |
| 템플릿 저장 | 템플릿만 바뀌며 날짜 일정은 자동으로 바뀌지 않음 |
| 날짜에서 `기본 템플릿 적용` 선택 | 템플릿의 앱과 시간대를 그 날짜에 복사 |
| 날짜 직접 설정 | 그 날짜에만 지정한 앱과 시간대 저장 |
| 일정이 없는 날짜 | 아무 앱도 차단하지 않음 |
| 날짜 일정 삭제 | 해당 날짜를 미설정 상태로 되돌림 |
| 홈에서 차단 시작 | 차단 감시가 시작되고 대상 앱 진입 시 차단 화면 표시 |
| `현재 일정 동안 해제` 선택 | 현재 앱의 현재 차단 구간만 해제 |

### 시간 경계

- 차단 시작 시각은 포함하고 종료 시각은 포함하지 않는다. 예: 09:00~18:00은 18:00에 해제된다.
- 같은 앱의 겹치거나 이어진 시간대는 하나의 연속 차단 구간으로 취급한다.
- 자정을 넘는 시간대는 지원하되, 편집 화면에 `다음 날`을 명시한다.
- 자정을 넘는 시간대는 시작 날짜의 일정으로 처리한다.
- 시작과 종료가 같은 입력은 허용하지 않고, 종일 차단이 필요하면 별도 옵션으로 표현한다.
- 기기의 현지 날짜와 시간을 기준으로 일정을 적용하는 것을 기본안으로 한다.

## 6. 첫 버전의 범위

### 포함

- 앱 선택.
- 앱과 시간대를 담은 기본 템플릿.
- 여러 차단 시간대 직접 입력.
- 월간 달력과 날짜별 일정 편집.
- 시간표에 따른 앱 차단 및 차단 안내.
- 즉시 해제.
- 기기 내 설정 저장.
- 차단에 필요한 권한 상태 확인 및 설정 안내.

### 이후 검토

- 계정, 서버 동기화, 기기 간 공유.
- Google Calendar 등 외부 달력 연동.
- 상세 사용 통계와 습관 분석.
- 하루 사용량·실행 횟수 제한.
- 웹사이트 차단.
- 비밀번호나 타인 승인으로 해제하는 강제 차단 모드.
- iOS 버전.

이 범위 구분은 첫 버전을 작게 만들기 위한 제안이며, 사용자가 명시적으로 제외를 확정한 목록은 아니다.

## 7. Android 구현 전 검증할 사항

기본 앱 차단은 사용 정보 접근으로 전면 앱을 확인하고, 다른 앱 위에 표시 권한으로 차단 화면을 띄운다. 웹사이트나 화면 요소를 차단하지 않으므로 접근성 서비스는 사용하지 않는다. 다음 항목은 실제 기기에서 확인해야 한다.

- 대상 앱 실행을 감지하고 차단 안내를 표시하는 방법.
- 이미 대상 앱을 사용 중일 때 차단 시작 시각이 되면 제한을 적용하는 방법.
- 권한 미허용·철회 시 동작과 사용자 안내.
- 재부팅, 백그라운드 제한, 절전 상태 이후 일정 복구.
- 기기 시각·시간대 변경 시 일정 재계산.
- 배포 방식에 따른 권한 사용 및 심사 요건.

권한이나 실행 상태 때문에 차단할 수 없으면 화면에 정상 차단 중이라고 표시하지 않는다. 시스템 설정 변경이나 앱 삭제까지 막는 것을 이 기획의 목표로 삼지 않는다.

## 8. 완료 판단 기준

아래 기준은 위 초안 제안 규칙을 채택했을 때의 검증 기준이다.

- 사용자가 앱과 시간을 직접 입력하고 저장하면 앱을 다시 열어도 설정이 유지된다.
- 템플릿을 선택한 날짜에 누르면 앱과 시간대가 복사된다.
- 템플릿을 바꿔도 이미 저장한 날짜의 일정은 바뀌지 않는다.
- 날짜마다 서로 다른 앱과 시간대를 저장할 수 있다.
- 일정이 없는 날짜에는 차단이 발생하지 않는다.
- 차단 시간 안에는 대상 앱에 제한이 적용되고 시간 밖에는 정상 사용 가능하다.
- 차단 시작 전에 사용 중이던 대상 앱에도 시작 시각부터 제한이 적용된다.
- 일정 저장 뒤 권한이 준비되면 수동 시작 없이 차단 감시가 실행된다.
- 차단 중인 앱을 열면 즉시 차단 화면이 표시된다.
- 자정을 넘는 일정, 겹치는 일정, 월 경계에서도 정해진 규칙대로 동작한다.
- 필요한 권한이 없으면 사용자가 차단 불가 상태와 필요한 조치를 확인할 수 있다.

## 9. 남은 제품 결정

- 앱 이름과 시각 디자인.
- 해제 시간을 구간 전체가 아닌 5분·10분으로 제한하는 선택 모드.
- 개인 설치용 APK를 우선할지, 스토어 배포까지 포함할지.

이 문서의 기능과 동작 기준을 바탕으로 MVP를 구현했다. 다음 단계는 실제 Android 기기에서 제조사별 백그라운드 동작과 오버레이 권한 흐름을 확인하는 것이다.

## 10. 현재 구현과 실행

현재 MVP는 Android 기본 API와 Java로 작성되어 있으며 외부 라이브러리, 계정, 서버를 사용하지 않는다. 일정과 앱 선택은 기기의 `SharedPreferences`에 저장한다.

구현된 기능:

- 검색·아이콘·패키지명이 있는 런처 앱 목록에서 차단 대상 선택.
- 앱과 여러 시간대를 담은 기본 템플릿 입력.
- 월간 달력에서 날짜별 템플릿 적용 또는 직접 일정 입력.
- 날짜별 서로 다른 앱과 시간대 저장, 자정을 넘는 일정 처리.
- 사용 정보 접근과 오버레이를 이용한 대상 앱 감지 및 차단 화면 표시.
- 차단 감시 중 지속 알림과 재부팅 후 복구.
- 현재 앱의 현재 연속 차단 구간 즉시 해제.

```powershell
$env:JAVA_HOME='E:\game\tools\jdk-17\jdk-17.0.20.1+1'
$env:ANDROID_SDK_ROOT='E:\game\tools\android-sdk'
./gradlew.bat assembleDebug
```

생성되는 APK는 `app/build/outputs/apk/debug/control.apk`에 있다. 설치 후 앱에서 기본 템플릿을 편집하고 날짜 또는 이번 달 일~목에 적용한 뒤 `사용 정보 접근`, `다른 앱 위에 표시`, `접근성 서비스`를 허용하고 `차단 시작`을 누르면 차단이 동작한다. 당월 차단 일정 모두 삭제는 기본 템플릿을 유지한 채 해당 달의 날짜별 일정만 지운다.

### 개인 기기에 테스트 설치

인터넷·메신저·파일 앱에서 직접 연 개발용 APK는 출처와 서명이 알려지지 않아 Play Protect 경고가 발생할 수 있다. 개발 중에는 Android의 공식 개발 도구인 ADB로 설치한다.

1. 휴대전화에서 개발자 옵션과 USB 디버깅을 켠다.
2. USB로 PC에 연결하고 휴대전화에 표시되는 디버깅 허용 창을 승인한다.
3. 프로젝트 폴더에서 다음 명령을 실행한다.

```powershell
.\install-debug.ps1
```

Play Protect 자체를 끄는 방법은 사용하지 않는다. 다른 사람에게 배포하려면 서명된 release AAB를 Play Internal Testing 또는 Closed Testing으로 먼저 배포하고, 민감 권한과 foreground service 용도를 Play Console에 신고해야 한다.

앱은 전면 앱의 패키지 이름과 실행 시각만 기기 안에서 확인한다. 화면 내용이나 키 입력은 읽지 않으며 외부로 데이터를 전송하지 않는다. 경쟁 제품 조사와 권한 선택 근거는 [Android 앱 차단 앱 조사](docs/COMPETITOR_RESEARCH.md)에 정리했다.
